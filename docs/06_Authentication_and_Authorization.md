# Authentication and Authorization

---

# 1. Introduction

Authentication and Authorization are two of the most important security mechanisms implemented in the Digital Marksheet Management System (DMMS). Although these terms are often used together, they serve different purposes within the application.

**Authentication** is the process of verifying the identity of a user. It ensures that only registered users with valid credentials can access the system.

**Authorization** is the process of determining what an authenticated user is allowed to access or perform within the application based on their assigned role.

The DMMS implements a secure authentication and authorization system using **JSON Web Tokens (JWT)**, **React Context API**, **Protected Routes**, and **Role-Based Access Control (RBAC)**.

---

# 2. Objectives

The authentication and authorization system has been designed with the following objectives:

- Verify the identity of every user before granting access.
- Prevent unauthorized users from accessing protected resources.
- Implement Role-Based Access Control (RBAC).
- Maintain user sessions securely.
- Protect sensitive pages and APIs.
- Support automatic session restoration.
- Provide a scalable security architecture for future enhancements.

---

# 3. Authentication vs Authorization

Although closely related, authentication and authorization perform different functions.

| Authentication | Authorization |
|---------------|---------------|
| Verifies who the user is. | Determines what the user can access. |
| Requires login credentials. | Requires an authenticated user. |
| Performed first. | Performed after authentication. |
| Returns a JWT token upon success. | Grants access based on the user's role. |

### Example

```
User Login
     │
     ▼
Authentication
     │
     ▼
Identity Verified
     │
     ▼
Authorization
     │
     ▼
Access Granted According To Role
```

# 6. Login Process

The login process begins when a user submits valid credentials through the Login page.

```
User
   │
   ▼
Enter Employee ID & Password
   │
   ▼
Click Login
   │
   ▼
authService.js
   │
   ▼
Axios POST Request
   │
   ▼
Backend Authentication
   │
   ▼
JWT Generated
   │
   ▼
User Object Returned
   │
   ▼
Save Token
   │
   ▼
Navigate to Dashboard
```

### Login Steps

1. The user enters their Employee ID and Password.
2. The Login button triggers an API request.
3. The backend validates the credentials against the database.
4. If authentication is successful, a JWT token is generated.
5. The backend returns the authenticated user's information along with the token.
6. The frontend stores the token and user details.
7. AuthContext updates the global authentication state.
8. The user is redirected to the dashboard corresponding to their role.

# 7. JWT (JSON Web Token)

The application uses **JSON Web Tokens (JWT)** to securely identify authenticated users.

A JWT is generated by the backend after successful authentication and is sent to the frontend.

```
Login Success
      │
      ▼
Generate JWT
      │
      ▼
Return Token
      │
      ▼
Store Token
      │
      ▼
Future Requests
```

### Benefits of JWT

- Stateless authentication.
- Reduced server-side session management.
- Fast authentication.
- Secure identity verification.
- Easy integration with REST APIs.

# 9. Session Restoration

One of the key features of the authentication system is automatic session restoration.

When the application starts, the AuthContext checks whether a valid authentication token already exists.

```
Application Starts
        │
        ▼
AuthContext
        │
        ▼
Check Local Storage
        │
   ┌────┴────┐
   │         │
Found      Not Found
   │         │
   ▼         ▼
Restore    Login Page
Session
```

### Session Restoration Steps

1. React application initializes.
2. AuthContext loads.
3. Local Storage is checked.
4. Existing user information is restored.
5. Authentication state is updated.
6. User remains logged in without entering credentials again.

This provides a seamless user experience after refreshing the browser.

```

      │
      ├── User
      ├── Token
      ├── Loading
      ├── Login()
```

- Update authentication state.

# 11. Authorization

After a user has been successfully authenticated, the next step is **Authorization**.

Authorization determines **what resources, pages, and functionalities an authenticated user is allowed to access**.

The Digital Marksheet Management System implements **Role-Based Access Control (RBAC)** to perform authorization.

---

## Authorization Flow

```
User Login
      │
      ▼
Authentication Successful
      │
      ▼
Read User Role
      │
      ▼
Role Verification
      │
      ▼
Permission Check
      │
      ▼
Grant or Deny Access
```

Unlike authentication, authorization occurs on every protected page request.

---

# 12. Role-Based Access Control (RBAC)

The application follows the **Role-Based Access Control (RBAC)** security model.

Every authenticated user belongs to exactly one role.

Current roles include:

- Administrator
- Head Teacher
- Class Teacher
- Subject Teacher

Each role has its own:

- Dashboard
- Sidebar Menu
- Accessible Pages
- Features
- Permissions

---

## Role Assignment

After successful login, the backend returns the authenticated user's role.

Example:

```
Backend
      │
      ▼
User Object
      │
      ▼
Role
      │
      ▼
Frontend
```

The frontend uses this role to determine which pages should be accessible.

---

## Dashboard Mapping

| User Role | Dashboard |
|------------|-----------|
| Administrator | /admin |
| Head Teacher | /head-teacher |
| Class Teacher | /class-teacher |
| Subject Teacher | /subject-teacher |

This mapping is managed centrally using the `ROLE_BASE_PATHS` configuration.

# 16. Authorization Middleware

After verifying the JWT, the backend performs authorization.

```
JWT Verified
      │
      ▼
Read User Role
      │
      ▼
Required Role
      │
      ▼
Compare Roles
      │
      ▼
Grant / Deny Access
```

The authorization middleware ensures that users cannot access resources outside their assigned role.

Example:

- Class Teacher cannot access Admin APIs.
- Subject Teacher cannot manage employees.
- Head Teacher cannot perform administrator-only operations.

# 19. Security Best Practices

The authentication and authorization system follows several security best practices.

## Authentication

- Validate every login request.
- Never expose passwords.
- Store passwords in hashed form.
- Use JWT for secure authentication.

---

## Authorization

- Verify user role before granting access.
- Protect every sensitive route.
- Restrict access to APIs.
- Use centralized role definitions.

---

## Session Management

- Restore valid sessions automatically.
- Remove session on logout.
- Prevent unauthorized access after logout.

---

## Frontend Security

- Protect routes using ProtectedRoute.
- Prevent authenticated users from accessing public pages.
- Store authentication state centrally.
- Avoid duplicate authentication logic.

# 21. Summary

The Digital Marksheet Management System implements a secure authentication and authorization mechanism using JWT, React Context API, Protected Routes, and Role-Based Access Control (RBAC). Authentication verifies the identity of users, while authorization determines the resources they are permitted to access.

By separating authentication from authorization and enforcing security checks at both the frontend and backend, the application ensures that only authenticated users can access protected resources and that each user interacts only with the features assigned to their role. This architecture provides a scalable, maintainable, and secure foundation for future enhancements and additional user roles.
